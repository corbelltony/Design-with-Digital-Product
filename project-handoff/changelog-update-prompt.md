# Repeatable changelog and test update prompt

Use with [the detailed maintenance workflow PDF](changelog-update-workflow.pdf). The user operates the real physical Raspberry Pi; AI assists with planning, code analysis, organizing evidence, and documentation.

> Update Cheddar Hub's test report and changelog using ONLY the dated Git commits, release records, owner-performed tests, and authentic screenshots or original videos I supply. Preserve historical entries. For each workflow, record the date/time, hardware and software environment, version/release or commit, exact input and numbered actions, expected and actual outcomes, PASS/FAIL/NOT TESTED, and source filename/timecode. Keep the operator's physical observations separate from automated tests or AI analysis. For any bug fix, use a prior real failure or a clearly labeled isolated retrospective reproduction; run the same steps under matched conditions after the fix, and report regressions. Organize the changelog under Added, Improved, Fixed, and Known issues, with actual dates and IDs. Do not fabricate performance gains, speech transcripts, audio measurements, deployment actions, or missing test results. Keep evidence in original form and redact credentials, account details, and private paths. Flag anything not verified, and do not remotely change or restart my Pi without explicit approval. Produce an updated report, changelog, source map, and evidence index.

**Owner review before publishing:** confirm the new screenshots actually depict the claimed screen and the supporting videos have the correct original audio. Check that no private information or credentials appear in screenshots or frame captures.
